Every classic Evolution CMS tag, written verbatim in a Latte template and resolved normally - followed by the same six things done through the Latte functions aLatteX registers, which take expressions instead of literals.

Read this page's template

The three sections around this text come from the template aLatteX Demo: EVO syntax - Elements → Templates, category aLatteX demo; in the package it is demo/templates/evo-syntax.latte. Find:

  • section #passthrough - all six tag forms written straight into a Latte template. They survive because EvoSyntaxBridge swaps each one for a token before Latte reads the file and puts it back afterwards.
  • section #functions - evoChunk(), evoSnippet(), evoUncachedSnippet(), evoTv(), evoSetting() and evoPlaceholder(). These take expressions, so the tag name can be computed - look for the snippet call assembled inside a {foreach}, which the classic syntax cannot do.
  • section #order - which parser runs when, and why a tag produced by a snippet is still resolved while a Latte tag produced by one is not.

The same six forms, live in this content field

This text is content, not a template, so Latte never sees it - but the Evolution CMS parser runs over it exactly as it runs over the template's output. Every tag below is doing its job right now:

  • [*pagetitle*] - document field: [*pagetitle*]
  • [*alxSubtitle*] - template variable: [*alxSubtitle*]
  • [(site_name)] - system setting: [(site_name)]
  • [~2~] - document URL: [~2~]
  • {{aLatteXDemoBadge}} - chunk: {{aLatteXDemoBadge}}
  • [[aLatteXDemoClock]] - cacheable snippet: [[aLatteXDemoClock]]
  • [!aLatteXDemoClock!] - non-cacheable snippet: [!aLatteXDemoClock!]

With parameters, and setting a placeholder the header chunk prints: [[aLatteXDemoList? &items=`chunk||snippet||setting||placeholder` ¬e=`Set from the content field of [*pagetitle*].`]]

Reload the page twice: only the non-cacheable clock moves. That is the whole difference between the two snippet forms, and it is easier to see here than in any explanation.
