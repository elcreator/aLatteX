Latte processes the template and stops. Chunks and snippets are expanded afterwards by Evolution CMS, which does not call Latte again - so a chunk full of {$vars} prints them as text. This page shows the three ways round that.

Read this page's template

The numbered sections come from the template aLatteX Demo: Chunks and snippets - Elements → Templates, category aLatteX demo; in the package it is demo/templates/chunks-and-snippets.latte. Read it together with the chunk aLatteXDemoCard (Elements → Chunks), which is Latte source rather than finished HTML. Find:

  • section #literal - the same chunk pulled in twice, once with the EVO tag and once with evoChunk(). Both print its braces verbatim: evoChunk() runs during Latte's pass but only returns the chunk, it does not compile it.
  • section #rendered - aLatteXDemoLatte with &chunk and a &vars JSON object: a second, deliberate Latte pass started from PHP. Also the &code form, which compiles an inline string.
  • section #inverted - usually the better answer. The {foreach} stays in the template and the chunk stays a lump of markup with placeholders.
  • section #snippet-output - a snippet's return value is spliced in after Latte, so EVO tags in it resolve and Latte tags in it do not.

Both routes, live in this content field

Content is parsed by Evolution CMS only, which makes it the cleanest place to see the difference: the two lines below pull the same chunk, and only one of them renders it.

Included the ordinary way - Latte source arrives as text

{{aLatteXDemoCard}}

Through aLatteXDemoLatte - compiled by a second pass

[[aLatteXDemoLatte? &chunk=`aLatteXDemoCard` &vars=`{"title":"Rendered from the content field","body":"Same chunk as above. This copy went through the plugin engine a second time, started by a snippet.","tags":["content","chunk","second pass"]}` ]]

Inline Latte, no chunk involved

[[aLatteXDemoLatte? &code=`

Document {$id}: {$pagetitle|upper}

` &vars=`{}`]]

The last one is worth a second look: {$pagetitle|upper} typed directly into this field would print as text, but handed to aLatteXDemoLatte as &code it compiles. Nothing about the field changed - what changed is who read the string.
