Six pages, one template each, installed by composer demo:install. Together they exercise every construct aLatteX can be asked to render: Latte 3 in full, all six Evolution CMS tag forms, the helper functions this plugin registers, and the places where the two syntaxes rub against each other.

Everything here is ordinary content. Open Elements → Templates and read the template beside the page it produced - that is what the demo is for. When you are done, composer demo:remove takes all of it away again.

Read this page's template

Everything around this paragraph comes from the template aLatteX Demo: Home - Elements → Templates, category aLatteX demo; in the package it is demo/templates/home.latte. Open it beside this page and find:

  • {define layout, string $title, array $pages} - the whole page shell as one reusable block, called once from {include layout, title: ..., pages: $pages}.
  • {define content, array $pages} - the middle of the page, which is where [*content*] sits and so where this text is pasted in.
  • Built in Latte, from the same list and Built by a snippet, through a chunk - the same index rendered twice, once by a {foreach} and once by aLatteXDemoList. Two routes, one result: that is the comparison the page exists to make.

Live in this content field

A resource's content is not a Latte template - Latte renders the template and finishes before [*content*] is substituted. Evolution CMS parses this text afterwards, so EVO tags written here do run. These are real, not screenshots:

  • Document field: [*pagetitle*], id [*id*].
  • System setting: [(site_name)].
  • Chunk: {{aLatteXDemoBadge}}
  • Snippet with parameters: [[aLatteXDemoList? &items=`templates||chunks||snippets` &class=`alx-list`]]
  • Link built from a document id: the basics page.

A Latte tag typed here stays text - {$pagetitle} prints as {$pagetitle}, because nothing compiles this field. The Latte basics page shows that side by side.
