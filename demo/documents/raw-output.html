Braces belong to two parsers here, and each has to be told separately to leave them alone. This page covers Latte's escape hatches, the fact that none of them stop the Evolution CMS parser, and the two innocent-looking expressions that aLatteX's tag protection mistakes for EVO tags.

Read this page's template

The sections around this text come from the template aLatteX Demo: Raw output - Elements → Templates, category aLatteX demo; in the package it is demo/templates/raw-output.latte. It is the one template worth reading in the editor rather than in the browser, because the source and the output are the whole comparison. Find:

  • section #braces - {l} and {r}, the two tags that print a brace.
  • section #syntax-off - {syntax off}, which switches Latte off for a whole region, and what it does not switch off.
  • section #escaping - context-aware escaping, and |noescape for when you mean the markup.
  • section #evo-verbatim - how to show an EVO tag on a page instead of running it. Latte's escape hatches do not help: the CMS parser runs after Latte and sees whatever Latte printed.
  • section #gotchas - the two expressions that look like EVO tags to the bridge's regex. Worth knowing before you write one by accident.

The same problem, in this content field

Content is simpler than a template: Latte never reads it, so braces need no escaping at all. This line contains {$pagetitle} and {if $x}{/if} and nothing had to be done to protect them - they are just text.

EVO tags are the opposite. They do run here, so showing one means breaking it up with HTML entities, exactly as the template does:

  • Written &#91;*pagetitle*&#93;, it shows as [*pagetitle*] - the tag as text.
  • Written normally, it runs: [*pagetitle*].
  • Same for a chunk: {{aLatteXDemoBadge}} as text, and {{aLatteXDemoBadge}} as the chunk.

The entity is resolved by the browser, long after both parsers have finished, which is why it is the one escape that always works. A <code> wrapper is not an escape - the CMS parser does not care what element a tag sits in.
